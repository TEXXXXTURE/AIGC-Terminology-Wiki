## 定义

推理优化（Inference Optimization）是指在「模型已经训练好、要把它跑起来服务用户」这一阶段，通过各种工程手段让它**更快、更省显存、更便宜**的一整套技术。一句话说清：训练是「一次花大钱把模型教出来」，推理是「之后每一次被调用都要花钱」——调用次数远大于训练次数，所以把单次推理压下去，整体成本就能大幅下降。它和[量化](../01-底层原理/量化.md)、[KV Cache](../03-表层概念/LLM/KV Cache.md) 等技术紧密交织。

## 原理

推理优化的瓶颈通常在三处：显存（尤其是长上下文下[K V Cache](../03-表层概念/LLM/KV Cache.md)占的大头）、计算（每生成一个 token 都要过的海量矩阵乘）、以及延迟（自回归「一个字一个字蹦」的串行本质）。对应手段也分几类：显存侧用[PagedAttention](PagedAttention.md)这种分页管理减少碎片、把 KV Cache[量化](../01-底层原理/量化.md)压缩；计算侧用[量化](../01-底层原理/量化.md)把权重压到低精度、用更优的算子（如 FlashAttention / SageAttention）；延迟侧用[投机解码](投机解码.md)让小模型先猜、大模型再验，一次出好几个 token。它们通常由[推理引擎](推理引擎.md)（vLLM / TGI / SGLang 等）统一调度落地。

## 由来与历史

推理优化随大模型商用而变得关键。2022 年 ChatGPT 引爆需求后，如何把千亿模型低成本地服务海量用户成了工程焦点。2023 年 vLLM 提出[PagedAttention](PagedAttention.md)（arXiv:2309.06180），把显存利用率大幅提升；同年投机解码（Leviathan 等，arXiv:2211.17192）等并行解码思路成熟。此后[量化](../01-底层原理/量化.md)（GPTQ / AWQ / GGUF）、连续批处理（continuous batching）、以及针对注意力的近似加速（SageAttention）等方法共同把单位推理成本年年压低，直接推动了本地部署和边缘推理的普及。

## 应用

对使用者来说，推理优化决定了「你的 12GB 显卡能不能跑、跑得快不快、 concurrent 多少人」。本地用 llama.cpp / Ollama 跑模型本质是推理优化在消费级硬件上的体现；线上服务则靠 vLLM 这类引擎撑住高并发。代价与权衡也真实存在：量化换来省显存，可能掉一点精度；投机解码换来低延迟，要额外跑一个小模型。理解它，能帮你在「显存 / 速度 / 画质（或准确率）」三角里做清醒取舍。
